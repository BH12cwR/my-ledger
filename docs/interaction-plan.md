## 1. 信息架构与导航调整

### 现状
底部导航 4 项：首页 `/` · 明细 `/transactions` · 统计 `/stats` · 我的 `/settings`，中间为「记一笔」FAB。

### 目标
底部导航 2 项 + FAB：**账单** `/` · **+**（记一笔） · **资产** `/assets`。
其余入口上移到账单页顶部栏的 4 个图标：**搜索**、**日历/日期**、**统计**、**我的**。

```
账单页顶栏：[ 2026年9月 ▾ ]                  [🔍] [📅] [📊] [👤]
                    └ 月份选择抽屉              │     │     │     └ /settings（我的）
                                              │     │     └ /stats（统计）
                                              │     └ 日期选择抽屉
                                              └ /search（搜索账单）

底部导航：         [ 账单 ]        [ + ]        [ 资产 ]
                      /        /transactions/new    /assets
```

### 路由映射（含新增/下线）

| 路由 | 变更 | 说明 |

## 2. 全局交互规范（本期统一）

1. **底部抽屉（Bottom Sheet）取代居中弹窗**：设计稿中的「选择日期」「选择扣款账户」均为底部弹层，含圆角、拖拽感、关闭按钮。当前项目只有居中 `Dialog`，需新增 `BottomSheet` 抽屉壳，并复用于日期、账户两处。
2. **分组列表**：账单页按「自然日」分组、搜索页按「自然月」分组。组头形如 `09.27 前天   支:195.59` / `2026年10月   支:1950.00`，右侧为组内小计。
3. **数字键盘记账**：记账页金额不再用输入框，改为底部固定键盘（1–9 / 0 / . / ⌫ / − / + / 再记 / 保存）。
4. **分段控件**：`支出 / 收入 / 转账`（记账）、`月 / 年`（统计）、`支出 / 收入 / 全部`（统计）共用同一套结构（`bg-muted/60` 容器 + 圆角项）。**（期 6 修订）**活跃态按场景分两套：口径切换（支出/收入/全部、记账类型）用类型色实底，粒度/视图切换（月/年）用白底胶囊 —— 这与设计稿本身一致，不再强行统一为一套。
5. **环境徽章与占比条**：统计页每行显示 环比徽章（▲ 涨 / ▼ 跌）+ 占比进度条，颜色取自分类色。
6. **空值展示**：**（期 6 修订）**按页拆分 —— 账单页「最近七日支出」的 0 值柱保留占位并显示 `0.00`；分类详情页 12 个月柱状图的 0 值柱不显示柱顶金额。原文「一律显示 `0.00`」与设计稿不符。

## 3. 逐页方案

### 3.1 账单页（`/`，稿 1/2）

**现状**：首页 = 预算卡 + 本月结余卡 + 今日卡 + 本月支出 Top5 + 最近账目（限 5 条）。

**目标**
- 顶部栏：月份选择器 `2026年9月 ▾`（点击开日期抽屉）+ 搜索/日历/统计/我的 4 图标。
- 蓝色渐变「月结余」大卡：左上标题、居中大字金额、底部一行 `月收入: 16009.45  月支出: 6586.53`。右上账本标签不渲染（决策 6）。
- 「最近七日支出」卡：标题 + `共计 855.51` + 7 根柱状图（柱顶金额，X 轴为相对星期 `周三…周二`）。
- 流水列表：按日分组，组头小计（支/收），行 = 分类图标 + 分类名 / 备注（二级）+ 金额（右，支出红 / 收入绿）+ 账户名（右二级）。
- 移除：预算卡、今日卡、Top5（Top5 能力已由统计页分类排行覆盖）。

**涉及改动**
- `src/app/(app)/page.tsx` 重写；组件 `TransactionRow` 增强（二级备注/账户名、日期分组场景、转账样式）。
- 数据：月结余与收支走 `/api/stats/summary`；近七日走 `/api/stats/trend?granularity=day&from&to`（均已存在）。
- 流水加载：前端分页拉取 + 前端按日分组（决策 4）。

**实现期决定（期 5 落地时确认）**
- **行点击打开「账目详情抽屉」**，而不是直接跳记账页。原因：旧的 `/transactions` 明细页是当时唯一能删除 / 退款的地方，该路由收敛为 `/` 之后必须有个落脚点；新抽屉复用 `components/transaction/detail-sheet.tsx`，内含详情、编辑、退款、删除（删除两段式确认）。
- 搜索页 `/search`、账户明细页 `/assets/[id]`、分类详情页 `/stats/category/[id]` 的流水行同样接这个抽屉，四处「流水行点击」行为保持一致。
- 删除 / 退款成功后调用方清空已追加的分页并重取列表与汇总，避免列表里残留已删记录、或「共 N 笔」与行数不一致。
- **（期 6 裁决）行首改为「类型色小圆点」**：设计稿的四处列表画的都是小圆点，本节原文写的「行 = 分类图标 + …」是误读。四处（账单页 / `/search` / `/assets/[id]` / `/stats/category/[id]`）统一改回小圆点，颜色沿用类型色（支出 rose / 收入 emerald / 转账 blue），行高随之变矮、单屏能容纳更多记录。

### 3.2 日期选择抽屉（稿 1 / 5）

**现状**：无。明细页用 `input[type=month]` + 上下月按钮；统计页用 `input[type=month]`。

**目标**（两种变体共用一个抽屉壳）
- 通用头部：标题「选择日期」+ 关闭 `X`。
- 变体 A（账单页，稿 1）：
  - 「显示方式」三选：`按月 / 按年 / 全部`（图标）。
  - 「月份起始日」一行，值 `01`，可展开选择 1–28。
  - 年份横滑（2028…2024，当前年高亮）。
  - 月份 4×3 网格，选中月高亮。
- 变体 B（记账页，稿 5）：
  - 月份导航 `2026年9月 ▾` + `< >`。
  - 日历网格（周日–周一–…–周六）。
  - 底部快捷：`今天 / 昨天 / 前天`。
  - 底部操作：`取消` / `确定`。

**涉及改动**
- 新增 `BottomSheet`、`MonthPicker`（变体 A）、`CalendarPicker`（变体 B）。
- `lib/dates.ts` 需补：相对日文案（今天/昨天/前天）、按「月份起始日」计算账期区间、月份加减。
- **决策 1**：「月份起始日」引入，存 `localStorage` 本地偏好（默认 1 号）。需新增读取/写入的 hook 与「按起始日计算账期区间」工具函数；账单页/统计页的「本月」区间口径随之改变（不进数据库、不跨设备同步）。

**实现期决定（期 6 落地时确认）**
- 「显示方式」三选落地为 `lib/dates.ts` 的 `BillRangeMode = "month" | "year" | "all"`，三种模式的区间口径：
  - `month` —— `resolveMonthRange(month, monthStartDay)`，即账期；
  - `year` —— 该年的 `01-01 ~ 12-31`（自然年，不受起始日影响）；
  - `all` —— 由 `GET /api/transactions/range` 给出的最早 / 最晚业务日；**一笔账都没有时回落到当前账期**（不能传空区间给接口 —— 它在缺区间时默认「最近 30 天」，那不是「全部」）。
- 大卡标题随之切换：`2026年9月结余` / `2026年结余` / `累计结余`，底部两项的「月收入 / 月支出」在非按月模式下去掉「月」字。
- 抽屉内容按模式收窄：只留「月份起始日 + 月份网格」给按月；按年只显示年份横滑（点年份即选中并关抽屉）；全部模式不提供可点项，只给一句说明，靠 X 关闭。
- 「显示方式」由 `month-picker.tsx` 的 `onModeChange` 是否传入来控制 —— 统计页不传，退回纯月份选择（它自己有「月 / 年」分段，不需要这里的开关）。
- 「显示方式」与「月份起始日」只改口径、**不关闭抽屉**；点月份 / 年份才关闭。

## 4. 数据模型与接口影响（转账）

### 4.1 现状（已具备 vs 缺失）

| 项 | 状态 |
| --- | --- |
| DB `transactions.kind` CHECK 含 `transfer` | ✅ [migrations/0001_init.sql](../migrations/0001_init.sql) |
| DB `transfer_peer_id` 列 | ✅ 存在但**全项目零使用** |
| `TransactionRecord.kind` 含 `transfer` | ✅ |
| 列表过滤 `kind=transfer` | ✅ `listTransactionsQuerySchema` 用 `transactionKindSchema` |
| 创建/更新 `kind=transfer` | ❌ `createTransactionSchema`/`updateTransactionSchema` 用的是 `categoryKindSchema`（仅 expense/income） |
| 统计 `kind=全部` | ❌ `statsQuerySchema.kind` 仅 expense/income |
| 账户余额含转账 | ❌ `getAccountBalances` 的 `CASE` 对 transfer 计 0 |

### 4.2 转账建模（决策 2：采纳方案 A）

- **方案 A（推荐）单记录**：`account_id` = 转出账户，新增列 `to_account_id` = 转入账户；`amount_cents` 保持正数。优点：两端天然一致，编辑/删除无需协调；与设计稿「一条转账记录」一致。
- 方案 B 双记录（未采纳）：两行经 `transfer_peer_id` 关联，但两行 `kind` 同为 `transfer` 且 `amount_cents > 0`，**无法区分方向**，需再引入方向列，复杂度更高。

→ 已采纳方案 A。闲置的 `transfer_peer_id` 随之清理（迁移 0006 中 `DROP`；实现期已确定：该列全项目零使用，直接删除而不是保留空列）。

**校验补充**：转账时 `categoryId` 必须为空、`toAccountId` 必填且 ≠ `accountId`。

### 4.3 统计与余额口径修正

1. `getSummary` / `getDashboardOverview`：`COUNT(*)` 会计入转账 → 需改为「仅 expense/income 计笔数」，转账单独计数（搜索汇总的「转账/还款」要用）。
2. `getDailyTrend` / `getMonthlyTrend`：金额 CASE 已忽略 transfer ✅，无需改。
3. `getAccountBalances`（方案 A 下）：需双向下账 —— 转出账户 `-amount`、转入账户 `+amount`；当前 SQL 只按 `t.account_id` join，需改为 `UNION ALL` 或两次聚合合并。
4. `getCategoryBreakdown`：已按 `kind=?` 过滤，转账天然不入分类统计 ✅。
5. `TransactionDto`：新增 `toAccountId` / `toAccountName`（转账展示）。
6. 退款：仅对 `expense`，不受影响 ✅。

### 4.4 测试影响
`tests/integration/transactions.test.ts`、`tests/integration/stats.test.ts` 需补转账用例（创建/编辑/删除、余额双向、统计不计入收支、笔数口径）。

### 9.6 期 6 走查新增的发现（已修）

浏览器实测（CDP 驱动，15 张截图）除了验证上表各项之外，还暴露出两个静态检查照不出来的问题：

1. **按金额排序与按日分组互斥** —— 「账单列表」抽屉最初复用 `GroupedList`，分组按天重排把金额排序切碎，同一天被拆成多段。已改为平铺列表（`groupBy="flat"`）。详见 §3.11。
2. **环形图卡名与设计稿不符** —— 原实现按口径叫「支出结构 / 收入结构」，稿件固定叫「分类统计」。已改。详见 §3.5。

顺带确认：二级页隐藏导航后，筛选页的吸底按钮不再与导航重叠（`确定吸底 = true`，且该页无导航）。
