## 1. 信息架构与导航调整

### 现状
底部导航 4 项：首页 `/` · 明细 `/transactions` · 统计 `/stats` · 我的 `/settings`，中间为「记一笔」FAB。

### 目标
底部导航 2 项 + FAB：**账单** `/` · **+**（记一笔） · **资产** `/assets`。
其余入口上移到账单页顶部栏的 4 个图标：**搜索**、**日历/日期**、**统计**、**我的**。

```
账单页顶栏：[ 2026年9月 ▾ ]                  [🔍] [📅] [📊] [👤]
                    └ 月份选择抽屉              │     │     │     └ /settings（我的）

底部导航：         [ 账单 ]        [ + ]        [ 资产 ]
```

## 2. 全局交互规范（本期统一）

1. **底部抽屉（Bottom Sheet）取代居中弹窗**：设计稿中的「选择日期」「选择扣款账户」均为底部弹层，含圆角、拖拽感、关闭按钮。当前项目只有居中 `Dialog`，需新增 `BottomSheet` 抽屉壳，并复用于日期、账户两处。
2. **分组列表**：账单页按「自然日」分组、搜索页按「自然月」分组。组头形如 `09.27 前天   支:195.59` / `2026年10月   支:1950.00`，右侧为组内小计。
3. **数字键盘记账**：记账页金额不再用输入框，改为底部固定键盘（1–9 / 0 / . / ⌫ / − / + / 再记 / 保存）。
4. **分段控件**：`支出 / 收入 / 转账`（记账）、`月 / 年`（统计）、`支出 / 收入 / 全部`（统计）统一为同一套分段样式。
5. **环境徽章与占比条**：统计页每行显示 环比徽章（▲ 涨 / ▼ 跌）+ 占比进度条，颜色取自分类色。
6. **空值展示**：0 值柱/行显示 `0.00` 而非隐藏（设计稿柱状图两侧为 0 仍占位）。

## 3. 逐页方案

### 3.1 账单页（`/`，稿 1/2）

**现状**：首页 = 预算卡 + 本月结余卡 + 今日卡 + 本月支出 Top5 + 最近账目（限 5 条）。

**目标**
- 顶部栏：月份选择器 `2026年9月 ▾`（点击开日期抽屉）+ 搜索/日历/统计/我的 4 图标。
- 蓝色渐变「月结余」大卡：左上标题、居中大字金额、底部一行 `月收入: 16009.45  月支出: 6586.53`。右上账本标签不渲染（决策 6）。
- 「最近七日支出」卡：标题 + `共计 855.51` + 7 根柱状图（柱顶金额，X 轴为相对星期 `周三…周二`）。
- 流水列表：按日分组，组头小计（支/收），行 = 分类图标 + 分类名 / 备注（二级）+ 金额（右，支出红 / 收入绿）+ 账户名（右二级）。
- 移除：预算卡、今日卡、Top5（Top5 能力已由统计页分类排行覆盖）。

**涉及改动**
- `src/app/(app)/page.tsx` 重写；组件 `TransactionRow` 增强（二级备注/账户名、日期分组场景、转账样式）。
- 数据：月结余与收支走 `/api/stats/summary`；近七日走 `/api/stats/trend?granularity=day&from&to`（均已存在）。
- 流水加载：前端分页拉取 + 前端按日分组（决策 4）。

**实现期决定（期 5 落地时确认）**
- **行点击打开「账目详情抽屉」**，而不是直接跳记账页。原因：旧的 `/transactions` 明细页是当时唯一能删除 / 退款的地方，该路由收敛为 `/` 之后必须有个落脚点；新抽屉复用 `components/transaction/detail-sheet.tsx`，内含详情、编辑、退款、删除（删除两段式确认）。
- 搜索页 `/search`、账户明细页 `/assets/[id]`、分类详情页 `/stats/category/[id]` 的流水行同样接这个抽屉，四处「流水行点击」行为保持一致。
- 删除 / 退款成功后调用方清空已追加的分页并重取列表与汇总，避免列表里残留已删记录、或「共 N 笔」与行数不一致。

### 3.7 搜索账单页（`/search`，稿 6）

**现状**：无独立页；明细页内嵌关键词搜索（占位「搜索备注或分类名称」）。

**目标**：筛选行 `全部 ▾ | 筛选 ▾`（「日常账本」不渲染，决策 6）；搜索框占位「搜索：分类、备注、金额」+ 右侧筛选图标；「搜索汇总」卡（`共 3968 笔` + 排序按钮；五项：`支出 / 收入 / 结余 / 转账` / `退款`，**不显示「手续费」**，决策 3）；结果按月分组（组头 `2026年10月  支:1950.00`，行含日期 + 备注 + 账户）。

**涉及改动**
- 结果列表复用 `/api/transactions`（keyword / kind / from / to / categoryId / accountId）。
- **搜索需支持金额**：当前后端 `keyword` 仅匹配 `note` 与分类名 → 需扩展或前端本地过滤。
- 汇总卡：支出/收入/结余已有；「转账」依赖期 2 的转账数据；「退款」可由 `refunded_at` 聚合；「手续费」不展示（决策 3）。
- 「筛选」跳转 `/search/filter`。

**实现期决定（期 4 落地时确认）**
- 汇总卡与列表**共用同一段 WHERE**：新增 `GET /api/transactions/summary`（参数与列表接口完全一致，只是不分页、不排序），`total` 必然等于同条件下列表的 `total`，杜绝「汇总 5 笔、列表 3 行」。
- **关键字在服务端扩展为三路匹配**：备注 / 分类名 / 金额（金额按「元」保留两位小数后模糊匹配，整数或小数都能命中）。不做前端本地过滤——否则分页与总数都会失真。
- 新增 `sort` 参数（`desc` 默认 / `asc`）。汇总卡右上角的排序按钮直接改接口排序，而不是在前端重排已分页的结果。
- 退款口径**忽略类型筛选**（退款恒为收入记录，带上 `kind` 就永远统计不到），与分类详情页的 `refundCents` 保持一致。
- 结果列表复用 `GroupedList`（`groupBy="month"`）：组头为「2026年10月 支:1950.00」，行内保留日期（`09-27 快递费`）、账户名落在金额下方。
- 筛选条件**全部落在 URL 查询串**上（`window.history.replaceState` 同步，不用 `useSearchParams` 以免退出静态预渲染），从筛选页返回 / 刷新 / 前后退都能还原视图。
- 「日常账本」不渲染（决策 6）。
- 结果行的点击行为与账单页统一：打开账目详情抽屉（含编辑 / 退款 / 删除），不再直接跳记账页（期 5 落地时确认）。

**目标**：日期范围 chips（`全部 / 本月 / 上月 / 今年 / 去年 / 2025年~2026年`）+ 自定义起止日期；「分类」二级入口；底部「确定」。

**涉及改动**：新增页面；参数落回 `/api/transactions`。无多账本前提下，「账本成员」「选择账本」两块整体不渲染（决策 6）。

**实现期决定（期 4 落地时确认）**
- 第 6 枚 chip 由 `GET /api/transactions/range`（最早 / 最晚业务日）**动态生成**：同年显示 `2026年`，跨年显示 `2025年~2026年`；没有任何账目时不渲染该 chip。

- 「账本成员」「选择账本」整体不渲染（决策 6）。

### 3.9 资产 Tab（`/assets`，导航衍生）

**现状**：账户列表在「我的 → 账户」Tab，余额来自 `/api/stats/accounts`。

**目标**：新增底部导航第 3 项「资产」；页面展示总资产 + 按账户类型分组（现金 / 银行卡 / 信用卡 / 投资等）的账户余额列表；点账户进入账户明细。

**涉及改动**
- 新增 `src/app/(app)/assets/page.tsx`；复用 `/api/accounts` + `/api/stats/accounts`。
- 「我的」页保留账户**管理**能力（新增/编辑/归档/删除），资产页负责**展示**，避免两处重复维护逻辑。
- 余额口径需先修好转账（见 4.3），否则转账不会影响账户余额。

**实现期决定（期 5 落地时确认）**
- 「点账户进入账户明细」落为 `src/app/(app)/assets/[id]/page.tsx`：单个账户的余额大卡 + 累计汇总（支出 / 收入 / 结余 / 转账）+ 该账户全部流水（按月分组、分页追加、行点击开详情抽屉）。
- `/assets` 的总资产 = 全部账户余额之和；账户列表按类型分组（现金 / 银行卡 / 微信 / 支付宝 / 信用卡 / 其他），空组不渲染，与「我的 → 账户」的类型选项一一对应。
- 页面**只读**：不提供新增 / 编辑账户，需要时回「我的 → 账户」，保持「展示」与「管理」的边界。
- 为让「余额」与「流水」对得上，`/api/transactions` 的 `accountId` 条件由只匹配 `account_id` 改为 `(account_id = ? OR to_account_id = ?)` —— 转账对两端都有影响，只看转出会让流入该账户的转账凭空消失。该参数此前前端零使用，改动不波及既有页面。
- 该页不发 `/api/stats/*` 请求：汇总走 `/api/transactions/summary?accountId=`，与列表共用同一段 WHERE，因此「共 N 笔」必然等于列表总数。
- （期 5 走查后微调）两处**逐行重复**已去掉：`/assets` 的账户行不再重复「类型 · N 笔」中的类型（分组头已经给出类型，且「现金 / 现金」「支付宝 / 支付宝」明显是噪音），只留笔数；`/assets/[id]` 的流水行通过 `TransactionRow` 新增的 `showAccount={false}` 关掉金额下方的账户名（整页都是同一个账户）。

## 4. 数据模型与接口影响（转账）

### 4.1 现状（已具备 vs 缺失）

| 项 | 状态 |
| --- | --- |
| DB `transactions.kind` CHECK 含 `transfer` | ✅ [migrations/0001_init.sql](../migrations/0001_init.sql) |
| DB `transfer_peer_id` 列 | ✅ 存在但**全项目零使用** |
| `TransactionRecord.kind` 含 `transfer` | ✅ |
| 列表过滤 `kind=transfer` | ✅ `listTransactionsQuerySchema` 用 `transactionKindSchema` |
| 创建/更新 `kind=transfer` | ❌ `createTransactionSchema`/`updateTransactionSchema` 用的是 `categoryKindSchema`（仅 expense/income） |
| 统计 `kind=全部` | ❌ `statsQuerySchema.kind` 仅 expense/income |
| 账户余额含转账 | ❌ `getAccountBalances` 的 `CASE` 对 transfer 计 0 |

### 4.2 转账建模（决策 2：采纳方案 A）

- **方案 A（推荐）单记录**：`account_id` = 转出账户，新增列 `to_account_id` = 转入账户；`amount_cents` 保持正数。优点：两端天然一致，编辑/删除无需协调；与设计稿「一条转账记录」一致。
- 方案 B 双记录（未采纳）：两行经 `transfer_peer_id` 关联，但两行 `kind` 同为 `transfer` 且 `amount_cents > 0`，**无法区分方向**，需再引入方向列，复杂度更高。

→ 已采纳方案 A。闲置的 `transfer_peer_id` 随之清理（迁移 0006 中 `DROP`；实现期已确定：该列全项目零使用，直接删除而不是保留空列）。

**校验补充**：转账时 `categoryId` 必须为空、`toAccountId` 必填且 ≠ `accountId`。

### 4.3 统计与余额口径修正

1. `getSummary` / `getDashboardOverview`：`COUNT(*)` 会计入转账 → 需改为「仅 expense/income 计笔数」，转账单独计数（搜索汇总的「转账/还款」要用）。
2. `getDailyTrend` / `getMonthlyTrend`：金额 CASE 已忽略 transfer ✅，无需改。
3. `getAccountBalances`（方案 A 下）：需双向下账 —— 转出账户 `-amount`、转入账户 `+amount`；当前 SQL 只按 `t.account_id` join，需改为 `UNION ALL` 或两次聚合合并。
4. `getCategoryBreakdown`：已按 `kind=?` 过滤，转账天然不入分类统计 ✅。
5. `TransactionDto`：新增 `toAccountId` / `toAccountName`（转账展示）。
6. 退款：仅对 `expense`，不受影响 ✅。

### 4.4 测试影响
`tests/integration/transactions.test.ts`、`tests/integration/stats.test.ts` 需补转账用例（创建/编辑/删除、余额双向、统计不计入收支、笔数口径）。

## 7. 决策结论（原 8 项待确认，已于 2026-09-29 全部裁决）

| # | 议题 | 结论 |
| --- | --- | --- |
| 1 | 月份起始日 | **引入**，存 `localStorage` 本地偏好（默认 1 号），不进库、不跨设备 |
| 2 | 转账建模 | **方案 A**：单记录 `account_id`（转出）+ 新增 `to_account_id`（转入） |
| 3 | 搜索「手续费」 | **隐藏该项**，汇总卡只展示 支出 / 收入 / 结余 / 转账 / 退款 |
| 4 | 整月流水加载 | **前端分页拉取 + 前端按日分组** |
| 5 | 统计环比口径 | **上一同长度周期**（月比上一自然月、年比上一年），服务端一次返回两期 |
| 6 | 账本相关 UI | **全部隐藏**（「日常账本」「账本成员」「选择账本」均不渲染） |
| 7 | 旧路由 `/transactions` | **重定向到 `/`** |
| 8 | 顶栏 `⊕` 与标签 | `⊕` **不渲染**；标签选择**保留在记账页内** |
